## 一、雏形时代（v0 – v41）

- `v0_nearest` → `v3_sim`：从"派往最近星"到 **sim-greedy 雏形**（枚举候选 → 短程模拟 → 选最优），确立了贯穿全程的决策骨架。
- v10–v41：score 函数、ensemble、beam、prodweight、early/adaptive、imitate、shot_reject 等大量小试验。
- **关键突破**：
  - `v32_shotreject` —— **shot_model 拒绝层**（用学习模型判 P(capture) 拒绝打不下的目标），见 `docs/v32_shot_reject_突破.md`。
  - `v35_threshonly` —— **地图自适应阈值**，见 `docs/v35_地图自适应突破.md`。
  - `v36_cluster_dispatch` / `v36b_hybrid` —— cluster 派遣实验（结论见 `docs/v36_cluster实验_结论.md`）。

## 二、价值函数时代（v42 – v68）

主题：训练 V(state)→胜率 网络，并适配 4P。
- v42–v44：V 模型扩到 4P + KO 价值整合 → 4P 25%→30%，但 V 对位置 2/3 预测不准（训练数据偏 2P）。
- v45–v57：shot 阈值松紧、bigfleet、center、reinforce、V 偏置/非对称、V+sim 融合 —— **大多无效或互相打架**。结论：**V 提升空间小，简化值得**；**单一信号比融合干净**。
- v58–v60：horizon24（慢且误差大）、K22（回报递减）、去 sim（失败，sim 验证不可或缺）。
- **v61/v62（去对手模型）**：sim 时不模拟对手反而提升 —— **对手模型差时不如不要**（4P 尤甚）。
- **v67（v62_noVtight）**：v62 + 去 V + 紧阈值 → 4P 30%+，接近最优配方。

## 三、v69 里程碑 + 横向探索（v69 – v82）

- **⭐ v69（v62_4ponly_noVtight）= 第一个稳定里程碑**：v62 + 4P-only V + no opp model + tight threshold → 4P 30% / 2P 42%，Kaggle ~790。**后续所有标量版本的基础。**

- **❌ v80（MCTS）= 0%**：窄候选空间下 subtree avg 不能当 action 价值。
- **❌ v82（PPO / 离线 RL）= 不外推**：BC 在窄状态分布过拟合，PPO vs random 学到的对 swarm 无效。**教训：云上 RL 产物只能当 sparring partner，不能直接部署。**

## 四、swarm 应对时代（v83 – v100）—— v98 长期主力

诊断：**75% 的败局来自 swarmer 对手**，必须专门应对。
- **⭐ v83（swarmcounter）**：检测对手在飞舰队数量，触发"防御模式"。
- **⭐ v85（4pswarm）= 单次最大跳升 +10pp**：扩到 4P + **修 player_idx 致命 bug**（num_players 从 step-0 全中立的盘面推断永远算成 2P → `actions[2]` IndexError）。**bug 修复 > 算法创新。**
- **⭐ v86（combined）= Kaggle 峰值 1109**（含运气成分，之后回落 800–900）。
- **⭐ v93（twotier）**：light（≥3 fleets / expansion_deficit）+ heavy（≥6）两层触发。
- **⭐ v95（total_swarm）**：swarm 检测应用到全部候选评分，v98 之前最完整形态。
- v96（early swarm）+ v97（4P horizon 16→14）。
- **⭐⭐⭐ v98（horz2p）= 标量时代长期部署**：v97 + **2P SIM_HORIZON=12**（4P=16）。本地 4P 32% / 2P 46%。锁定超参：K=20、2P opp="starter"/4P="none"、两层 swarm 触发。
- v99（2P horizon10）/v100（2P K18）：**均比 v98 差**，确认 v98 是标量局部最优。

## 五、数据驱动反制时代（v101 – v126）—— v123 部署

构建了真实数据资产：`replays/{2p,4p}/`（998 真实回放）、`data/opponents_db.*`、`data/opponent_styles.*`，建立 meta 模型（见 `docs/Kaggle赛场对手与主流打法_数据建模.md`）。

- v101–v104：rank-aware / no-attack-first / chase-first / early-swarm —— **5 个 threshold tweak 全部 byte-identical to v98**（无边界可改）。
- **⭐ v123（swarmer_detect）= 部署**：基于 140 局真实分析，对真 swarmer（rate 5–10/turn）反制；触发阈值 3.0/turn 是本地无法构造、Kaggle 真 swarmer 必到的水位线，误触发极低；动作面极小（解锁防御预留 + shot 阈值 −0.1）。**本地全部 byte-identical to v98**，只能 Kaggle 验证激活。

**❌❌❌ proto1000 攻坚组（v105–v126，~17 个实验全失败）：**
- proto1000 = **~1000 launches/game**（v98 的 10x），trajectory-tracking 架构（global fleet/reinforcement trajectories + 8 行星 coop）。
- 失败清单：coop attack(v105/v121/v125)、reinforce(v106/v122/v129)、coop+reinforce(v107)、high-volume(v108→0%)、low-filter(v109)、reserve(v111→0%)、ensemble(v114→0%)、smart/always-hv opp model(v115/v116 = byte-identical，**证明 sim opp model 只改绝对 eval 不改相对 delta**)、bypass-sim pressure(v117→0%)、small-worthwhile probes(v126 −12pp)。
- **核心教训**：
  - "模仿对手 launches 数量"是错目标 —— proto1000 的高 volume 来自它自己的 target filter，机械复制"发 5 ship"而不复制完整 filter chain = 自杀。
  - v98 在 standard pool 是 **razor-edge 硬局部最优**，任何 ±1 launch 打破平衡。
  - 要赢 proto1000 必须完全重写范式 —— 这直接催生了下一时代的高 volume 骨干。

## 七、★ 范式转折：Producer / single-size 时代（Kaggle ~1180，+325）

**最大跳分**：发现竞品 notebook "Producer Hybrid v4"（Slawek Biel 公开的 `orbit_lite` 张量引擎），落地为 `single-size/`。
- **关键解锁**：旧记录"submission 只能 stdlib"是**错的** —— Kaggle 运行时**预装 torch/numpy**，submission 可 `import torch` + bundle 纯 py 包。
- **算法**：全向量化 sim-greedy + 精确稀疏 flow-diff 打分 + `safe_drain` 单 fleet size + 连续拦截 + 后勤层 regroup + 2P/4P 分治。`send_ships = safe_drain max`、后勤层占 launches 54%、偏好低 prod 近星稳扩、首发延迟到 step 12 攒兵大波。
- **自加 4P FFA**：leader_attack_bonus=0.035 / target_prod_bonus=0.08 / roi 1.55 / min_ships 5。
- **结果**：v133 856.9 → single-size **~1157–1180**，rank 687→585。这是**结构性碾压**，如实传递到 Kaggle（不受本地反相关影响）。

**本时代真正的产出 = 诊断（非 agent 提升）：**
- **冻结 bug**：4P horizon=13 下 flow-diff 把"单星吃大中立星"算成净亏船 → 孤星枯坐等死（占负局 ~18%）。是**评分缺陷**非几何。
- **regroup 振荡**：基线固有的 cosmetic 现象，调阈值无效，放弃修。
- **⭐ 失败根因（120 真实局）**：胜负双峰（胜=滚到 ~21 星，负=卡 ~8 星归零）；**机制 = 中期 ~4 星平台过早停扩**，非开局/几何/中后期。4P 负局**全是 rank 2**。

| 变体 | 改动 | Kaggle | 结论 |
|---|---|---|---|
| baseline | Producer-hybrid-v4 原样 | ~1180 | 基准 |
| v2 | 多源 coop(2P+4P) + 饥饿 bootstrap | 1066–1095 | ❌ 净负（4P coop 抽空星被第三方夺）|

## 八之二、★ 旁支：light-ver（外部竞品 1200，"少即是多"的反向验证）

`light-ver-1200-simple-orbit-intruder.ipynb` = 另一个 ~1200 分外部竞品（"Orbit Intruder w/ Simple Structure"），同 `orbit_lite` 引擎，但走**反方向哲学：结构极简 + 连续动态调节**。已解耦到 `external/lightver/main.py`，两个机制参数化（默认关）移植进 `search/agent_main.py`。

**它刻意"没有"的东西（与我们主干正相反）：**
- ❌ **无 multi-size tiers**（0.5/0.75/1.0）—— 只用单 `safe_drain` 满发。
- ❌ **无 FFA leader bonus 模块** —— 边际收益不值复杂度（**再次反证我们整季 4P 加 FFA 是错方向**）。
- ❌ **无 GRU / 学习型 controller**、❌ **无 phase 切换 / 硬阈值**、❌ **无重验证层**。

**它"有"的东西（核心 = 一个轻量动态函数 `_adjust_config`）：**
1. **增援风险 β=2.2**（ETA-aware 敌方增援建模，同 rmargin 的 `reinforce_size_beta`）—— 防打必败仗。
2. **连续动态 ROI**：每回合算 `ratio = 我方强度 / 榜首强度`，按**二次 deficit 曲线**平滑降 ROI（落后越多降越多，无硬阈值）；晚期（step>350 且落后）加时间紧迫额外降；落后 / 末 100 步 +1 wave。
3. **晚期候选抑制**：末 120 回合杀掉到达太晚的攻击 + 贬值晚期中立（减少终局浪兵）。
4. **3 档预设**：2P(ROI 1.40/h18)、3P(ROI 1.35/h15)、4P(ROI 1.25/h13/waves 5→6)。

**为何重要**：连续动态 ROI **正是对症 rmargin 真实软肋（中期被精确+施压型抢崩）的解** —— 落后时自动降 ROI 更激进扩张反扑，且**用连续曲线避开了 catchup/hoard/v111 的硬开关冻结坑**。

**本地战况（2026-06-16 commit 579ed9d）**：现有本地池太弱（rmargin 12/0 碾压 proto1000/bc_smart_v2/structured），**改用 light-ver 当强 foil**：light-ver h2h **8/4 打赢 rmargin**、对 exp48 也 8/4，用于去饱和/相对区分（h2h≠Kaggle 仍反相关）。combo（rmargin+两开关）h2h vs rmargin = 11/10/5（平衡 h2h 测不出"落后/晚期"机制，因为本地 foil 不会把我们打到落后）。**BC 路同时放弃**（逐星克隆到不了顶级强度）。

## 十、学习型价值自博弈联盟（direction-3，rl/）—— 管线就绪待训练

**动机**：手工变体在 Kaggle ~1170 封顶；根诊不是舰队规模/扩张（已与顶级相当），而是**决策执行深度** —— flow-diff 评估太近视。
**方案**：学一个 **value(state)→P(win)** 函数，用 **1-ply 价值搜索**替换近视 flow-diff，保留 Producer 健壮候选生成。
**避开 v82 外推失败的防御**：① **只学价值不学政策**（搜索层手写、鲁棒）；② **多样对手池**（Producer 变体 + structured/proto1000/orbitbotnext + 历史 value 快照），拒绝纯自博弈。

**管线组件**（`rl/`，已本地冒烟）：
- `features.py`：obs→10 维特征（训练/推理共用，纯 py）
- `value_net.py`：64 隐层 MLP（torch 训练）+ JSON 权重 + 纯 py 前向（无 torch 部署风险）
- `gen_selfplay.py`：多进程 league → (特征, rank1 胜负) jsonl
- `train_value.py`：CUDA 训练 + holdout AUC
- `value_agent.py`：**部署 agent** —— exp48 候选 + 3 档激进度(roi 1.0/1.5/2.5)用 V 值择优；**无权重时自动退化为纯 exp48**（保证不劣基线）
- `run_league.py`：gen→train→eval→快照迭代编排；`build_submission.py`：打包
- 速度 ~45–60ms/turn（远低于 1s）。

**现状**：架构完整、代码就绪，**awaiting 3060 机训练迭代**（早期 `value_data.json` 已采集）。关键迭代信号 = 本地 h2h 胜率（比 holdout AUC 反馈快），Kaggle 是最终裁判。这是**穿透 ~1180/1247 封顶**的换范式尝试。

## 十一、跨时代结论（防踩坑）

### ❌ 反复验证失败、不要再试
- **bigfleet**（v46/49/63/71）、**center bias**（v51/64）、**long horizon ≥20**（v58/76）/ **短 ≤10**（v99）、**K≠20**（v59/74/88/100）。
- **MCTS**（v80 0%）、**PPO/BC 政策部署**（v82 不外推）。
- **proto1000 攻坚全套**（v105–v126，~17 个，含 coop/reinforce/high-volume/reserve/ensemble）。
- **情景感知/phase 切换**（v132 惨败、exp42/45 回退）。
- **显式屯兵旋钮**（rmargin-hoard 无增益，reyhan 的屯是涌现的）。
- **无脑增进攻 / coop 在 4P**（平移非改善 + 抽空星被夺）。
- **regroup 阈值调参**（振荡来自公转非阈值可滤）。

### ✅ 有效的方向
1. **2P/4P 分流**（v48 起）：不同 horizon / opp model / 激进度。
2. **去对手模型**（v61/v72）：建模差时不如不要。
3. **swarm 应对两层触发**（v83/v93/v95）。
4. **bug 修复 > 算法创新**（v85 player_idx +10pp；NameError/evac 多次假阴）。
5. **范式升级 > 调参**（v133→single-size +325；single-size→multi-size 治平台）。
6. **multi-size 候选**（exp48 核心）+ **ETA-aware 增援余量**（rmargin/light-ver β）+ **趁火打劫 1.5**（f_ch 帮 4P）。
7. **连续动态 ROI**（light-ver）：按强度落后程度平滑降 ROI 反扑，**无硬阈值** → 避开 catchup/hoard/v111 的冻结坑，对症"中期被抢崩"。**待 Kaggle 验证。**

### ⚙️ 方法论铁律
- **本地↔Kaggle 反相关**只在边际改进成立；结构性碾压会传递。**别用本地排名选提交。**
- **Kaggle ±100 噪声**；<60 局分不可信；变体间 ±15–30 不可分。
- **遇负优化先查 bug/看对局**，别急着否定策略。
- **提交 Kaggle 前必须征得用户同意。**
