## 2. 关键诊断发现(本时代的真正产出)

### 2.1 冻结 bug(孤星枯坐)
- 现象:4P 某些图,起手孤星全程只发 4–12 次、卡 1 星等死(占真实负局 ~18%)。
- 根因:flow-diff 在 4P horizon=13 把"单星吃静态大中立星"算成净亏船(分 −13→−3 < roi 1.55)→ 拒绝扩张。**是评分缺陷,不是几何/够不着。**
- bootstrap 修法:owned≤1 且无在途时去 roi 强发 → 部分救活(seed6 pos2 launch 1→62 转胜),但 pos0/pos3 仍是真死局(周围中立星全吃不下)。

### 2.2 regroup 振荡("循环自己打自己")
- 现象:后勤层在两星间来回搬兵(基线 4P 68% 发射打向自己星、15 次 A↔B 反向)。
- 真相:**基线固有**(振荡最重的基线分却最高)→ cosmetic,非失分主因。`regroup_pressure_delta_min` 调高**无效**(振荡来自公转使压力大幅翻转,非阈值可滤)。**放弃修。**

### 2.3 反应式对手模型(方向④)的 v115 验证关
- v98 时代:改对手模型只动绝对 eval、不动相对 delta(白做)。
- **producer 不同**:按目标逐个打分,对手反应进 per-candidate delta。`validate_react.py` 测 12 帧 → **10/12 相对排序变** → 门过,可建。

### 2.4 ⭐ Kaggle 分噪声真相(本时代最重要)
- `orbit-wars-i-m-better.ipynb` 的 1287 分 agent 与基线**字节级相同**(仅差一空行)。
- 1287 = ref 53473016 在 6-8 只打 **24 局 1.3h 就冻结**的小样本幸运快照;同代码 62 局收敛到 ~1180。
- **结论:同代码 Kaggle public 分波动 ±100。变体间 ±15–30 差异全在噪声带,统计上无法区分。<60 局的分不可信。**

### 2.5 ⭐ 失败根因(120 真实局,WR≈49%)
- 胜负**双峰**:胜=滚到 ~21 星守住,负=卡 ~8 星归零,competitive 仅 2%。
- 64% 负局 = "没突破"(maxPC≤8)。归一化扩张曲线:
  - 10% 进度与赢家**打平**(都 2 星)。
  - **25–70% 我死卡 4 星,赢家爬到 10。**
  - 100% 我归 0、赢家 16。
- **机制 = 中期过早停止扩张(~4 星平台)**。非开局、非几何、非中后期。
- 4P 负局**全是 rank 2**(没抢到第 1,不是被联手打死)。

## 3. 已验证的教训(不要再犯)

- **无脑增进攻无效**:bootstrap/coop 把"没突破(64%)"平移成"过扩被团灭(34%)",是平移非改善,Kaggle 净负。
- **coop 在 4P 有害**:多源同时抽空星 → 第三方夺(撞 v133 R4 老问题)。
- **regroup 阈值调参无效**:振荡非阈值可滤。
- **本地弱池测不出对症改动**:catchup 只在落后时激活,本地始终领先 → 测不出(设计正确)。只能 Kaggle。
- **别追单次高分**:noise ±100;要看**持续、多局**站上基线。
