# 方案 B：自对弈 + 进化优化

## 核心思路

让 agent 在本地海量对战、记录结果，**根据胜负反馈自动调整参数 / 策略**——不靠手动直觉。

实际上**纯神经网络 RL 在这个项目里不太现实**（见后面"不推荐"那段）。可行版本是**进化 / 贝叶斯优化 over 高维参数空间**——把"训练"变成"参数搜索"，因为这游戏的好 agent 主要瓶颈不在表达能力，在参数协同。

## 分三档实现，从轻到重

### B1：扩展随机参数搜索（轻，1-2 h）

**已经做过**：5 个参数 × 12 trial → 47% (vs 强对手)。

扩展方向：
- 加更多参数：开局发兵触发条件、发兵比例、二轮 prune 容差、buffer 倍数等（10-15 个参数）
- 增加 trial 数到 50-100
- 评估时**同时用 2P + 4P**（避免 v20 那种 2P 过拟合）
- 加 weak 对手到评估（保证不退化）

**关键：评估混入 4P 局**。当前 v20 在 4P + 3 强对手只有 5%，因为参数没在那个场景调过。

写法：
```python
def fitness(params):
    score = 0
    # 2P vs 强 (权重 0.5)
    score += 0.5 * win_rate_2p(params, ["lb1224", "proto1000", "structured"])
    # 4P 混合 (权重 0.3)
    score += 0.3 * win_rate_4p(params, mixed_lineups)
    # 2P vs 弱 (权重 0.2，确保不退化)
    score += 0.2 * win_rate_2p(params, ["starter", "v2d_conserve"])
    return score
```

每次评估 ~30 局，约 4-5 分钟。50 次评估 = 3-4 小时。

**预期**：搜出更鲁棒的 v25，可能 50-55% 总胜率。

### B2：CMA-ES 进化搜索（中，4-6 h）

随机搜索是空间盲采样，CMA-ES 是带历史的——逐渐缩小到好的区域。

工具：`cma` Python 包（pip 装得到）

```python
import cma
es = cma.CMAEvolutionStrategy(initial_params, sigma=0.3)
while not es.stop():
    candidates = es.ask()  # 提议一批参数
    fitness_vals = [evaluate(c) for c in candidates]
    es.tell(candidates, fitness_vals)
```

每代 ~10 candidates × 30 局 = 5 分钟 × 10 = 50 分钟。
10-15 代收敛。**总 8-12 小时**。

**预期**：再压 5-10 ppt 胜率，55% → 60-65%。

### B3：真 RL 自对弈训练（重，**不推荐**）

理论上可以：
1. 定义状态特征（行星 owner / ships / pos、fleet 飞行向量等的张量表示）
2. 定义动作空间（离散化的目标 + 派船数选择）
3. 用 PPO / REINFORCE 训练策略网络
4. 自对弈生成轨迹，更新网络

**为什么不推荐**：

- **动作空间巨大**：每个 my_planet × 每个 target × 多个 ship 数 × 角度 = 100+ 离散动作。多个 my_planet 同时决策是组合爆炸。要扁平化或分层。
- **稀疏奖励**：500 步后的 win/loss = 唯一信号。需要 reward shaping，否则学不动。
- **本地 CPU 训练慢**：一局 5-10 秒 self-play。要 10,000+ 局才有可学到的策略。**至少 1-2 天 CPU 时间**。
- **自对弈陷阱**：agent 只学到打"和自己一样的对手"，可能对真天梯 bot 还是不行（同 v3p sim 的问题）。
- **环境近似**：我的 sim 不是 100% 精确（彗星 spawn 没模拟），训出来的 policy 可能利用 sim 漏洞而不是真技巧。

**结论**：除非有 GPU + 几天时间 + ML 经验，不要碰 B3。

### B4：模仿学习作为 RL 的引导

如果方案 A 拿到很多 replay 数据，可以用它**预训练**一个策略：

1. (state, top_player_action) 对训一个分类/回归模型（小 NN 或决策树）
2. 用这个模型作为 RL 的初始 policy
3. 再用 self-play 微调

但这要求 A 先成功，且需要 ML 基建。属于半年规模工作。

## 推荐路径：B1 + 4P 修正

实际上最高 ROI 是这个：

```
基于现有 search.py:
  1. 扩参数到 10 个（加开局触发、buffer、阶段切换阈值）
  2. fitness 混合 2P + 4P
  3. 跑 30-50 trial 随机搜索
  4. 拿到 v21 ~50-55%
  5. 用 CMA-ES 在 v21 附近精搜
  6. 收敛到 v22 ~55-60%
```

总时间 **6-10 小时**。

## 跟方案 A 的比较

| 维度 | A：replay 抽规律 | B1：进化搜索 |
|---|---|---|
| 时间 | 8-12 h（含等用户下载） | 6-10 h（纯自动） |
| 上限 | 60-65%（受 top 行为表达能力限制） | 55-60%（受当前算法骨架限制） |
| 风险 | 样本偏差、过拟合 | 多目标耦合时陷局部最优 |
| 黑盒边界 | 在边缘（看 replay 算"黑盒"）| 完全黑盒（不看任何选手内部） |
| 增量价值 | 引入新的候选生成 | 优化已有结构 |
| 后续可扩 | 可作为 B 的种子 | 比较死，做完就做完了 |

## 我的建议（实操）

**先 B1 跑起来**（自动、不需要等用户做事），同时**并行收集 replay 数据**（用户做这事），然后 A 做规律抽取，把规律编码成候选给 B1 搜出来的 v21 用。

具体：
1. **现在**：开 B1 多目标参数搜索（半小时-1 小时初见效果）
2. **同时**：让用户陆续下载 10-20 个 1700 / 1500+ 选手 replay
3. **B1 出 v21 后**：跑方案 A 的统计，看是否有"v21 没做但 top 选手都做"的事
4. **如果有**：把那些规律编码为候选，再跑一次小搜索 → v22
5. **如果没有**：v21 就是当前算法骨架下的极限，要进 B2 CMA-ES 或者推翻骨架重做

## 不会做的事

- ❌ 训练神经网络（B3）——CPU 太慢、ML 复杂度不匹配本地开发节奏
- ❌ 把 lb1224 当 sim 内对手用（虽然技术上能跑，但违反"黑盒"要求）
- ❌ 直接抄选手的 deep sim / mission 架构——重写他们的方案不是迭代我的方案
