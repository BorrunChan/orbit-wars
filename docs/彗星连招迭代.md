# 彗星连招迭代记录

> 自主迭代日志。原则:**连招是组合效应,不因单模块本地不好就砍**。提交需用户同意。
> 本地↔Kaggle 反相关,本地只作崩溃筛 + 相对趋势参考,真章 Kaggle。

## 目标
本地对 5 个下载的 ipynb 对手 (opp_ithe / opp_lightver / opp_exp48 / opp_theproducer / opp_reyhan) 稳定占优,核心是彗星战术连招。

## 框架(与用户讨论确定)
1. **彗星价值评估**:用 path 预测轨迹目标,只占"会划到肥的敌/中立目标"的彗星(止损没价值的)
2. **彗星占领**:boost 估值过 roi + 强制进 target 绕 proximity → 拦截移动彗星
3. **攻打策略**:实时选目标(每回合重评估) + 三计打敌后弱点(彗星投送到敌后,趁火/欲擒/擒王选弱点)
4. **离场前清仓**:彗星 step~84 消失前把驻军发出去(用户判断有用;本地实测害但反相关)
5. **防对手守**:打 drained 源 / 弱守 / 从意外方向(绕过 regroup 增援梯度)

## 基线 & 已知发现
- `default producer` vs 5 对手: 2P 平均 **56.7%** (lightver **33% 输** = 唯一打不赢的), 4P 混战夺冠 **47%**
- **彗星 base 依赖**: hoard producer base 彗星 **+6**(38→44); f_ch码(agent_main) base 彗星 **-10**(47→37)
- **清仓本地**: 价值定向版 31% < 无清仓 44%(本地害,但反相关待 Kaggle 验)
- **支线A 4P 单旋钮**(vs default 47): 出逃 **+6**(53,唯一有利); reserve0.4 **-27**/horizon偏离13 **-24**/size单 **-17**(大害); 欲擒/beta 微害; 趁火/hoard/防御/经济/中心性 无影响
- **params 失效铁律**: getcwd 读不到 → 必须硬编码或 import 机制才生效
- **真实 Kaggle 4P**: reyhan(纯producer default) 41.7% 最强; hyb6 1205 实为纯 default producer

### 迭代11: 学 Xander 多路并发 — 僵局破局失败 + 真因是防守 ★★
**(A) Kaggle 多路并发普遍性**:998 回放统计,**75-86% 的 player-game 达到 8+ 舰同时在空**,78% 有 3+ 小舰并发。低分段(<800)平均 33 并发舰(无脑高频),1200+ 反弹到 23(有组织多路)。**多路并发是 Kaggle 标准操作,不是 Xander 特例。**
**(B) 僵局破局机制(已实现于 hoard_cval)**:memory 跟踪 owned 创新高清零/否则+1 计停滞;`step≥70 + stall≥15 + owned≥4 + 有敌星` → 降 roi(1.5→1.05)+ 提 waves(7→10)+ 关 hoard。
- **触发正常但零效果**:debug vs lightver 触发 55/163 次(step88起),但 on/off **100局 byte-identical**(45/35/75/85/40 avg56)。
- **根因**:producer 的 `capture_floor` 在 `_tier_candidates` 上游就把"打不下的敌星"候选 `valid=False`(敌星守军+增援→floor高→drain不够)。降 roi 是 `_greedy_select` 阶段门槛,**管不到上游 floor**。僵局敌星要么 roi 本来就高(直接打)、要么判打不下(不发),**无 1.05-1.5 边际地带**。
**(C) 真因 = 防守**:debug 那局我方 step88 起 owned 8→6→2→1 崩盘,**触发后一直打敌星但自己星照丢**。Xander 局崩溃直接原因是**防守扛不住多路并发**,不是我方进攻不够。进攻向抓偏了重点。
- producer 已有 `max_defensive_targets=4`(2P)+ always-on regroup,但对 8 路并发不足。**本地 vs lightver/reyhan 能复现被打崩**(不像僵局进攻本地无场景)→ 防守向本地可验证。
**(D) 用户定向: 连招(进攻试探 + 防守)**。先攻防守(对症 + 本地可验证):A/B 测加强防御参数(max_defensive_targets 4→6/8 + regroup_delta 0.35→0.15)进行中。进攻向(放宽 capture_floor 试探,撞 v108/v117「兵力耗光」雷区)后做,需僵局专属 + safe_drain 护守军规避。

### 迭代14: 向高分看齐 — 彗星克制打敌(打瘦敌→回援) ★★
**高分段彗星用法实证**(534局真实回放, >1200 玩家 815 局次, 同判定逻辑):
| 分段 | 打敌兵% | 回援自己% | 打下敌星prod |
|---|---|---|---|
| **>1200** | **18%** | **76%** | 2.5 |
| 1000-1200 | 41% | 51% | 2.4 |
| 我们 hoard_lianzhao | 38% | 56% | 2.7 |
| 我们 lz_route | 52% | 48% | 2.6 |
- **认知反转**(我之前判断错): 「回援自己=浪费」是错的, **分越高回援越多(>1200 高达76%)**。彗星主流用法 = **占领当移动中转站做兵力回援/巩固**, 不是敌后强袭打肥。我们打敌比例(38-52%)远超高分(18%) = 在彗星上打敌太多(打瘦星+削弱没下=浪费)。
- **全段打下敌星 prod 都 2.4-2.7(瘦星)** → 彗星能打下的就是瘦星(肥星守得住), 即彗星本质是边际机制。
- **跳板完整性确认**(按波分段, 修正前误判): hoard_lianzhao 24/25波完整(占领→投送→离场清空, 白丢=0), lz_route 9/11。机制走得完整, 问题在打敌目标质量(瘦+浪费)。
**实现**: `comet_attack_min_prod=4.0`, 彗星源星(清仓 + 正常发兵两处)不打瘦敌(prod<4) → 该候选 -inf → 兵落入 leftover 由 regroup 回援/巩固。
- **A/B**: 只改清仓 = 零差异(清仓占发兵小头, 大头是彗星作普通源星的正常发兵); 覆盖正常发兵后生效: 夺冠 52% 不变, 但 rank[21,17,2,0]→**[21,19,0,0] 消除 2 个 rank3**(克制保兵少崩)。小幅正向+不崩, Kaggle 验。
- **当前 4P 完整机制**(向高分看齐): 彗星价值占领 + **彗星克制打敌/回援** + 三计 + **evac 出逃保兵(+22)**。两改进同向(高分=保兵+回援+克制)。
