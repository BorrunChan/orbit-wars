> **本文档是硬约束 source-of-truth。开发任何新版本前必读，不得违反。**

---

## ⚠️ 必须遵守的硬约束（违反 = 直接判负 / 提交失败）

以下规则**没有任何回旋空间**，下一个 agent 在改 main.py 前请逐条对照：

### A. 动作合法性
1. **只能从自己拥有的行星发射** — `from_planet_id` 必须 owner == player
2. **发射 ships 数量 ≤ 该行星当前 garrison** — 不能透支
3. **`num_ships` 必须为整数**
4. **`direction_angle` 是弧度**（不是度），`0 = 右`、`π/2 = 下`（注意 Y 轴向下）
5. **不能从"即将离开棋盘的彗星"发射** — 彗星先于发射阶段被移除
6. 返回**空 list `[]`** 表示本回合不动，不要返回 `None`

### B. 决策时间
- **每回合 1 秒**（`actTimeout = 1`），超时本回合按"无动作"处理
- 有 `remainingOverageTime` 总额度（秒），但要省着用
- v98 当前实测平均每回合 < 200ms，仍有余量

### C. 提交格式
- **必须有 `main.py` 在根**，里面有 `def agent(observation, configuration)` 函数
- 多文件提交：打包成 `submission.tar.gz`，`main.py` 在根
- macOS 打包要 `COPYFILE_DISABLE=1` 防 `._junk` 文件（已在 `scripts/build_submission.py` 处理）
- 依赖：**只能用 Python 标准库 + kaggle_environments 提供的**（不能 `pip install` 私货）
- 每天最多 5 次提交，最新 2 次进入评测池

### D. 评测规则（不可改变）
- 初始 `μ₀ = 600`
- 局间 TrueSkill 更新（贝叶斯）
- **2P 1v1 / 4P FFA**（不要假设对手只有 1 个）
- **截止日期：2026-06-23 23:59 UTC**
- 截止后 2026-06-24 → ~2026-07-08 继续跑直到 leaderboard 收敛

## 二、游戏规则

### 2.1 棋盘
- **100 × 100 连续空间**（不是网格），原点在**左上角**
- **太阳**：中心 `(50, 50)`，半径 `10`，舰队穿过太阳即被摧毁
- **4 重对称**：所有行星和彗星都按 `(x, y)`、`(100-x, y)`、`(x, 100-y)`、`(100-x, 100-y)` 镜像放置

### 2.2 行星 (Planet)
**数据格式**：`[id, owner, x, y, radius, ships, production]`

| 字段 | 含义 |
|---|---|
| `id` | 唯一 ID |
| `owner` | 玩家 ID `0-3`，`-1` = 中立 |
| `x, y` | 位置（连续坐标） |
| `radius` | 半径 = `1 + ln(production)`，production 越大行星越大 |
| `ships` | 当前驻军 |
| `production` | 整数 `1-5`，每回合自动产 `production` 艘船 |

**行星类型**：
- **Orbiting（旋转）**：`orbital_radius + planet_radius < 50` 的会绕太阳转，角速度 `0.025-0.05 rad/turn`（每局随机），用 `initial_planets` + `angular_velocity` 推算位置
- **Static（静止）**：离中心远的不转

**地图组成**：
- 20-40 个行星 = 5-10 个对称组（每组 4 个）
- **至少 3 组保证 static**
- **至少 1 组保证 orbiting**

**初始 ships**：在 `5-99` 之间（偏低）；**家园行星固定 10 ships**

### 2.3 家园 (Home Planets)
- 1 组对称行星被随机选为出生点
- **2P**：玩家在对角的 Q1 和 Q4
- **4P**：每个玩家拿组里的 1 个行星

### 2.4 舰队 (Fleet)
**数据格式**：`[id, owner, x, y, angle, from_planet_id, ships]`

- `angle`：飞行方向（弧度）
- `ships`：舰队规模（**飞行途中不变**）

### 2.5 舰队速度
**公式**：
```
speed = 1.0 + (maxSpeed - 1.0) * (log(ships) / log(1000)) ^ 1.5
```
- 1 ship → `1.0 units/turn`
- ~500 ships → `~5`
- ~1000 ships → `~6`（最大）
- **舰队越大越快**（这是核心机制，影响"是否合发"决策）

### 2.6 舰队移动
- 每回合按 speed 走直线
- **被移除的情况**：
  1. 飞出 100×100 边界
  2. 穿过太阳（线段进入 sun radius）
  3. 撞上任何行星（线段进入 planet radius）→ 触发战斗
- **连续碰撞检测**：检查整条线段，不只是端点

### 2.7 发射
- `[from_planet_id, direction_angle, num_ships]`
- **只能从自己的行星发**
- **不能超过 garrison**
- 舰队出生在行星边缘（按 direction 方向）
- 一回合可以从多个行星发多次

### 2.8 彗星 (Comet)
**临时出现的高椭圆轨道天体。**

- **半径**：1.0（固定）
- **production**：1 ship/turn
- **初始 ships**：1-99 取 4 次最小（偏低），一组 4 个共享
- **速度**：`cometSpeed = 4.0 units/turn`
- **生成时机**：步 50, 150, 250, 350, 450（每次 4 个，每象限 1 个）
- **识别**：观察里有 `comet_planet_ids`（哪些 planet id 是彗星）
- **彗星可以被占领、产船、发射**（同 planet 规则）
- **彗星离场时**：和上面 garrisoned 的船一起消失。**离场发生在发射阶段之前** → 不能从即将离场的彗星发船
- 观察里 `comets` 字段包含 `paths` 和 `path_index` → 可预测未来位置

### 2.9 回合执行顺序（严格）
```
1. 彗星离场（已飞出去的移除）
2. 彗星生成（特定步）
3. 玩家发射（处理 action）
4. 行星产船（all owned including 彗星）
5. 舰队移动（检 OOB / sun / planet 碰撞）
6. 行星旋转 + 彗星推进（被扫到的舰队进战斗）
7. 战斗结算
```

### 2.10 战斗结算
当 ≥1 个舰队撞行星（或被旋转/移动的行星扫到）：

1. **按 owner 分组**，同 owner ships 相加
2. **最大力量打第二大** → 差值幸存
3. 幸存者：
   - **同 owner = 行星方** → 加入驻军
   - **不同 owner** → 和 garrison 打：
     - 攻方 > 守方 → **行星易主**，garrison 翻成攻方剩余
     - 攻方 ≤ 守方 → 守方保留，garrison -= 攻方
4. **两个攻方平手 → 全灭**（无幸存者）

### 2.11 游戏结束
**结束条件**（满足任一）：
- 达 **500 步** 上限
- **只剩 1 个或 0 个玩家**有任何行星或舰队

**胜负**：`final_score = 我的行星总 ships + 我的舰队总 ships`，最高分赢

## 三、Observation 完整字段

| Field | Type | 说明 |
|---|---|---|
| `planets` | `[[id, owner, x, y, radius, ships, production], ...]` | 全部行星（含彗星） |
| `fleets` | `[[id, owner, x, y, angle, from_planet_id, ships], ...]` | 全部活跃舰队 |
| `player` | `int` | **你的玩家 ID `0-3`** |
| `angular_velocity` | `float` | 行星旋转角速度（rad/turn） |
| `initial_planets` | 同 planets 格式 | **开局时**的行星位置（推算旋转用） |
| `comets` | `[{planet_ids, paths, path_index}, ...]` | 活跃彗星组数据 |
| `comet_planet_ids` | `[int, ...]` | 哪些 planet id 是彗星 |
| `remainingOverageTime` | `float` | 总剩余超时预算（秒） |

### 历史坑（前任经验）
- ⚠️ **`initial_planets` 在 step 0 全是中立** → 不能从 initial_planets 推 `num_players`，必须从 `raw_planets + raw_fleets + player` 推。v85 之前这个 bug 导致 4P slot 2/3 永远报 IndexError。

## 四、Action 格式

```python
return [[from_planet_id, direction_angle, num_ships], ...]
```

- `from_planet_id`：你拥有的某个 planet id
- `direction_angle`：弧度，**0 = 右，π/2 = 下**（Y 轴向下！）
- `num_ships`：整数，不超过 garrison
- 不动 → 返回 `[]`

### Agent 函数签名
```python
def agent(observation, configuration):
    # observation 是 dict（也支持 .player 等属性访问）
    # configuration 含 episodeSteps / actTimeout / shipSpeed / sunRadius / boardSize / cometSpeed
    return []
```

### 官方便利 named tuples
```python
from kaggle_environments.envs.orbit_wars.orbit_wars import (
    Planet, Fleet, CENTER, ROTATION_RADIUS_LIMIT
)
planets = [Planet(*p) for p in obs.get("planets", [])]
fleets = [Fleet(*f) for f in obs.get("fleets", [])]
```

## 五、Configuration 参数

| Parameter | Default | 说明 |
|---|---|---|
| `episodeSteps` | 500 | 最大回合数 |
| `actTimeout` | 1 | **每回合秒数（硬约束！）** |
| `shipSpeed` | 6.0 | 舰队最大速度 |
| `sunRadius` | 10.0 | 太阳半径 |
| `boardSize` | 100.0 | 棋盘边长 |
| `cometSpeed` | 4.0 | 彗星速度 |

## 六、本地开发与提交流程

### 依赖
```bash
pip install "kaggle-environments>=1.28.0"  # 必须 ≥ 1.28.0
pip install kaggle  # CLI
```

### 本地跑一局
```python
from kaggle_environments import make
env = make("orbit_wars", configuration={"seed": 42}, debug=True)
env.run(["main.py", "random"])
for i, s in enumerate(env.steps[-1]):
    print(f"Player {i}: reward={s.reward}, status={s.status}")
env.render(mode="ipython", width=800, height=600)
```

### 提交
**单文件**：
```bash
kaggle competitions submit orbit-wars -f main.py -m "v99 描述"
```

**多文件**（我们用这个）：
```bash
# 我们用 scripts/build_submission.py 打包（已设 COPYFILE_DISABLE）
COPYFILE_DISABLE=1 tar -czf submission.tar.gz main.py sim.py shot_model.py value_4p_model.py
kaggle competitions submit orbit-wars -f submission.tar.gz -m "v99 描述"
```

### 监控
```bash
kaggle competitions submissions orbit-wars          # 查状态
kaggle competitions episodes <SUBMISSION_ID>        # 看打过的局
kaggle competitions replay <EPISODE_ID> -p replays/ # 下 replay JSON
kaggle competitions logs <EPISODE_ID> 0             # 下日志（0/1/2/3 是 player index）
kaggle competitions leaderboard orbit-wars -s       # 看 leaderboard
```

## 八、给开发者的提醒（基于硬约束的反推）

1. **`num_players` 推断不能用 `initial_planets`**（step 0 全中立）—— 见 v85 bug
2. **Y 轴向下！** `atan2(target.y - mine.y, target.x - mine.x)` 给的 angle 直接能用（坐标系一致），但脑子里画图时不要把 `+y` 当成"上"
3. **舰队大小影响速度** —— `sim.py` 必须用官方公式，不能简化成"线性"
4. **战斗顺序**：发射 → 产船 → 移动 → 旋转扫 → 结算。预测下一步必须按这个顺序
5. **彗星离场在发射之前** —— 不要试图从快走的彗星调兵
6. **不能用第三方库** —— 我们的 sim.py / shot_model.py / value_4p_model.py 全是纯 Python stdlib 编译，这是硬约束的产物
7. **1 秒 actTimeout** —— 任何新加的搜索/RL 必须算清楚 worst case 时间
