## 一、本轮实验

### v108_high_volume.py
**设计**：在 v98 sim greedy 之后，对每个剩余 budget ≥ 5 的 mine，向最近的 unowned target 发射 `mine.ships // 3` 个 ships。**模仿 proto1000 的 high-volume 策略**。

**结果**：**0/30 = 0%**（全输）

**根因**：`mine.ships // 3` 是按 ship pool 1/3 发，叠加 v98 已有发射，每星每回合送出 30-40% 兵力 → 5-10 回合后行星耗空 → 任何敌方 fleet 都能翻盘。bench 总时长 105s vs v98 330s = 游戏平均 130 步 vs 200+ 步 = 早死。

### v109_low_filter.py
**设计**：保留 v98 sim greedy，但：
- shot_threshold 在 2P 强制 ≤ 0.10（让更多 candidate 通过 shot_model）
- K 从 15 → 40 在 2P（more candidates 进入 sim greedy）

**结果**：**11/30 = 37%** (-10pp vs v98)

| Opp | v98 | v109 |
|---|---|---|
| mlhybrid | 33% | 17% |
| lb1224 | 67% | 50% |
| structured | 67% | **83%** ✅ (+1W) |
| proto1000 | 0% | **0%** |
| orbitbotnext | 67% | 33% |

只有 structured 提升 +1W，其他都退。**proto1000 仍 0/6**。

## 三、关于 proto1000 的最终假设

proto1000 vs v98 = 0/36 这种"完全统治"在战术层面**不太可能是配置问题**，更可能是：

### 假设 A: 初始局面决定
- 在 2P 1v1 bench 中 seed=0..2 都用相同初始 planet 配置
- proto1000 在这些初始配置上有先天优势（比如离中立 planet 更近）
- 任何 v98 改动都无法翻盘

验证方法：跑 seed=3..10 看是否相同模式。

### 假设 B: proto1000 的目标选择函数更优
proto1000 的 `get_custom_score` (line 24-51)：
```
score = (100 - dist) + 15*production + 10*enemy_bonus - 0.7*total_ships - 2*eta
```
直接奖励距离近 + 高产 + 敌方 + 低 ETA。v98 用 `base_value / (min_ships + T)` 是 value/cost 比。可能 proto1000 的 score 在快速扩张阶段更精准。

验证方法：把 proto1000 的 score 函数 port 到 v98 作为候选 ranking，看 vs proto1000 是否改善。

### 假设 C: proto1000 的 60-tick threat prediction 反制 v98
proto1000 用 `get_planets_under_attack` 预测 60 步内的所有威胁，比 v98 的 sim_horizon=12 远得多。**v98 的每个发射都能被 proto1000 早 50 步预知并调防**。

验证方法：log proto1000 的 `under_attack` 字典，看哪些 v98 launches 被 proto1000 提前知道。

## 四、关键反思：方法论错误

我犯了 3 个迭代错误：

### 错误 1：把 proto1000 当 "swarmer" 测试集
proto1000 不是 swarmer，是 **高 volume 结构化 agent**。docs/对手战术库.md 之前归类是"较弱"——错。v98 vs proto1000 = 0/6 是因为它本质上是个**强对手**，不是因为它是 swarmer。

### 错误 2：以为 v98 在 standard pool 的 47% 反映 Kaggle 47%
真实 Kaggle 27 replay 显示 v98 输给的对手 launches 范围 187-1501（**不限于 1000+**）。本地 proto1000 (1051) 只是 Kaggle 真实分布的一个极端样本。**搞定 proto1000 ≠ 搞定 Kaggle**。

### 错误 3：连续 6 个实验都基于"加东西到 v98"思路
v105/v106/v107/v108/v109 都是在 v98 sim greedy 框架上**叠加**新逻辑。v98 在这个框架下是 local optimum——任何叠加都引入 regression。要超越 v98，可能需要：
- 完全不同的决策框架（不是 sim greedy）
- 或针对 proto1000 风格的专用模式（A7 detector + 完全替换决策路径）
- 或接受 v98 在 standard pool 的天花板，转用真实 Kaggle replay-bot 为测试集
