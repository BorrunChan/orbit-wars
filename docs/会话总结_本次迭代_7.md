- proto1000 无法从保守状态继续展开 → 失败

**Stateful sequential game 中，中途换 framework 不可行**。Adaptive routing 在 Orbit Wars 行不通。

## 三、本 session 学到的真理

### 真理 1：v98 是 absolute hard local optimum (standard pool)
- 加东西、减东西、调阈值、加 K、混合 — 全失败
- 13 个不同 angle 的实验都不能 superscore v98
- 这是非常 strong 的负面证据

### 真理 2：本地测试集都失败
- fake swarmer 太弱（不会扩张，被 v98 早期吞掉）
- replay-bot 不 reactive（动作不响应 v98 行为）
- 真正能击败 v98 的对手类型本地没有

### 真理 3：proto1000 的 0/6 是结构性死局
- 13 个实验都没拿 proto1000 vs v98 的一局
- 局部最优、初始 map 配置、proto1000 的精准 score function
- 这场对决在战术层面不可消解

### 真理 4：ensemble routing 在 stateful game 不可行
- proto1000 必须从 step 0 bootstrap
- 中途换 framework → style mismatch → 双输

## 五、所有可能的下一步方向（按概率排序）

### 几乎不可能成功（基于 13 实验证据）
- ❌ 任何 v98 incremental tweak
- ❌ 任何 v98 + 单一新策略的 stacking
- ❌ Ensemble routing
- ❌ 用 fake swarmer 测试集
- ❌ 用 replay-bot 测试集

### 可能值得试（理论 + 工程量大）
- ⚠️ **彻底放弃 v98 paradigm，从 0 设计新 agent**（30+ 小时工程量，外推不确定）
- ⚠️ **直接 Kaggle 测试** — submit v110 (proto fork) 看 Kaggle 段位变化（1-3 天反馈）
- ⚠️ **训练 reactive swarmer bot** — 用 PPO 学一个 reactive 对手（云上 RL infra 已有），用它测 v98 弱点
- ⚠️ **多人 4P swarm 动态分析** — 在 4P pool 我们 rank 2 比例高，可能 4P 还有空间

### 实际推荐
**接受 v98 是 paradigm 局部最优**。继续推 v98 到 Kaggle。
- 既然 13 个本地实验都不能超越 v98，本地空间已经穷尽
- 真正的 ground truth 是 Kaggle 实际 ranking
- 等 Kaggle 反馈 1-2 周，看真实段位走势再决定大方向
